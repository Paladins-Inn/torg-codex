# UI contract: `GET /`

- **Scope:** Anonymous and signed-in visitors see the same thumbnails for cards common to their existing Available Sourcebooks lists. Do not change list membership, order, empty-section behavior, category counts or DRM outcomes.
- **Success:** With JavaScript enabled and at least one supported thumbnail available, display the image using `{primaryProductId}-thumb140.jpg` first at every viewport width; the card also carries the `{primaryProductId}-thumb140.png` link for a single fallback attempt if JPEG fails. Display the entire image without distortion in a reserved 140 by 190 CSS-pixel frame, scaled proportionally if necessary. A narrower frame does not select a lower-resolution image. Reserve the same space before, during and after loading.
- **Navigation:** The picture and visible title share one keyboard-focusable link to the current Codex detail path. Give the picture alternative text naming the publication and name the link from the visible title to avoid duplicate announcements. The optional DriveThruRPG store button keeps its existing destination and behavior.
- **Failure:** With no suitable reference, emit no external image request. While loading, when both formats fail (network error, decode failure or blocking), or when JavaScript is disabled, show a local neutral frame without a broken-image indicator. The disabled-JavaScript case need not prevent the browser's initial image request. Homepage text, category navigation, publication links and store links remain visible and usable without waiting for image loading.
- **Attempt limit:** Allow at most two application-controlled image-source attempts per card: one JPEG and, only if it fails, one PNG. HTTP redirect hops do not count as additional attempts. The script must not retry either format.
- **Transport:** Image requests go directly from browser to public provider URL, without Codex credentials or a referrer. Do not introduce a proxy, remote preflight, broad content-policy exception or server-side store call. No REST contract changes.
- **Lifecycle:** The build and application startup neither download nor probe images. Rendering the card emits a link derived from the primary product ID, not a local copy. Adding a product must not require adding a thumbnail mapping.
